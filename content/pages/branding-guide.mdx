# Old MacDonald Had a School branding guide

This is the human-readable source for `/branding`. The page renders the same cast, materials, and component rules as a working reference. Do not recreate its visual language from memory. Reuse the named classes, canonical assets, and semantic HTML shown in the guide.

## Working rules

- A grade is a curriculum hub, not a character theme.
- Character colour belongs only to a character-specific component, scene, or activity.
- Use a `cast-*` class to make one character identity available locally. It must not recolour an entire grade page.
- Use a `material-*` class with `material-surface` to apply an authored, repeating production texture. Do not imitate paper, felt, cork, leather, thread, or fabric with CSS gradients or generated noise.
- Use the existing shadcn components for controls. The global theme supplies their colours, borders, and focus treatment.
- Preserve canonical portraits unchanged. Do not recolour, crop into a new face patch, or substitute them.

## Class contract

### Character context

```html
<aside class="cast-miss-hayley material-surface material-felt">
  <!-- Only content about Miss Hayley belongs here. -->
</aside>
```

`cast-miss-hayley` provides the local `--character-color`, `--character-texture`, and `--character-foreground` values. Other approved keys follow the same `cast-<name>` pattern.

### Material surface

```html
<article class="material-surface material-cardboard-paper">
  <!-- Readable lesson or planning content. -->
</article>
```

Approved material keys are `material-cardboard-paper`, `material-felt`, `material-woven-fabric`, `material-construction-paper`, `material-cork`, and `material-leather`.

## Asset and implementation rules

- Canonical portraits: `public/staff_and_students/`
- Repeatable materials: `public/design-assets/web-material-library-v1/`
- Cork: `public/design-assets/cork-board-kit-v1/`
- Fasteners: `public/design-assets/classroom-fasteners-v1/individual-icons/`
- Grade and subject icons: `public/brand-kit-icon-sheets/individual-icons/`
- Character badges use the matching transparent-circle portrait over its matching authored circle patch.
- Never use a blank felt rectangle marked `DO NOT USE`, a contact sheet, an atlas, a page composite, a Figma export, or a design exploration as a production component.

## Typography review notes

Typography is demonstrated visually on `/branding` but is not being changed in this pass. The current system uses the farm display face for short branded headings, the hand face for occasional expressive emphasis, and the farm body face for readable copy and controls. Future work should define where each belongs, size steps, line-height, and maximum heading lengths before changing page templates.

## Component reference

`/branding` is a working component reference. Its examples are live shadcn controls, rendered against this project’s global theme and approved asset classes.

| Component | Use it for | Do not use it for |
| --- | --- | --- |
| Button | Actions, navigational links styled as actions, and clear state changes | A generic `div` with a click handler |
| Input and NativeSelect | A real search, filter, or planning entry | Decoration or a fake form field |
| Tabs | Related panels in one location | Navigating to an unrelated route |
| Navigation menu and Dropdown menu | A compact list of related destinations or actions | A permanent page rail |
| Collapsible | Optional supporting detail | Primary content that users must discover |
| Sheet | Focused secondary work without leaving the current page | A full page layout replacement |
| Carousel | A finite, browsable sequence of cards | Hiding essential content from a desktop layout |
| Card and Separator | Grouped content and meaningful section boundaries | Drawing every page as unrelated decorative boxes |

## Brand-book organization

The live `/branding` page is a continuous scrollable brand book. Its spreads are foundations and materials, character identity, live controls, layout patterns, typography, and rules. The focused MDX page at `/branding/guide` is the scan-friendly source for the same contract.

When this guide grows, preserve those headings as section anchors. Add a focused route only when a component has enough variants, code examples, and usage rules to make the single page hard to scan. Every route must still link back to the overview.
